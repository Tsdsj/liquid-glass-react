## 最近一轮做了什么

**0.0.2**：把「在真实项目里第一天就会卡住」的两件事清掉——37 个会渲染元素的组件里有 25 个拿不到 `ref`，大半还只收 `className`。守它的探针在运行时和类型两层都测，因为 JSX 展开会跳过多余属性检查，光能编译不等于类型上接受；也正是这一层查出 `TabBar` 的 `ref` 落在内层 `div` 而不是 `<nav>`。另外把三条此前靠人眼查的设计规则改成开发模式告警，过程中发现守卫本身写错了：`globalThis.process?.env` 打包器不会替换，告警其实在生产环境里一直开着。文档站补上 import 片段、相关组件、源码链接、代码高亮、切页标题与焦点、更新日志页，以及窄屏下的吸顶目录菜单（过了一遍 Apple-Style-Review，五条发现修掉四条）。2.2 的三条疑点全部查过，**都没复现**，用例留下当回归守卫。

**alpha.5（全面审计）**：修掉「跨到另一个选项那一帧高亮块飞出整个框」——切换选项换掉槽位，而这一刻的位移是照旧槽位算的，相加就把它扔出一整段（实测轨道外 25px）。然后按 Apple-Style-Review 清单把 27 个组件与文档站整个过了一遍，六条发现全部修复，其中一条是 Blocker：所有浮层里的分段控件、开关、搜索框都在浮层的玻璃上又叠了一层自己的玻璃。详见 `../reports/hig-review.md` 第〇之〇节。

**alpha.4（反馈回路）**：alpha.3 让控件真正跟手之后暴露出一个更基本的问题——按住不动，控件也在抖。拖动要知道高亮块「原本该在哪」，办法是量出当前位置再减掉自己写进去的位移；但 CSS 的独立 `scale` 属性作用在 `transform` 之前，槽位偏移被形变乘了一遍，量出的原点带着误差，误差又进到下一帧的位移里，形成每帧震荡的闭环。现在槽位、位移、形变合成同一条 `transform`，缩放放最后。同时补上标签栏与侧边栏的拖动切换——此前高亮块能被拖走却决定不了任何事。

**alpha.3（手势与首帧）**：报告的六个问题都不在静态截图里。最要紧的一条是拖动——此前所有"可拖动"的控件，无论手指移多远，位移都被橡皮筋限制在十几像素内，看着像控件朝手指歪了一下而不是被带着走；形变也一开始拖就顶到上限，所以每次都一模一样。现在控件在自身行程内 1:1 跟手，形变来自速度与阻力。另外修掉了融合层交还画笔时的跳变、共享表面上主操作按钮没有底色（浅色下白字画在透明上）、导航链接触发浏览器原生拖拽、首帧回弹、浅色底色过亮，以及行进高光在指针越过左边缘时整圈乱转。详见 `../reports/hig-review.md` 第〇节。

**alpha.2**：把仓库展平成可发布的单包，修掉用户实测报出的七组缺陷，把组件页改成可查阅的形态、把全站文案换成面向使用者的说法，补齐逐组件的测试与审计。顺带修掉两个会让包在真实项目里直接用不了的问题：首屏主题脚本违反 CSP，以及打包过程丢掉了 `"use client"`。
