# 设计审查 — 0.2.0-alpha.2

对照 Apple 的人机界面指南与 Liquid Glass 指南，把 27 个组件逐个过了一遍，以及全站的分层、色彩、排版、形状、动效、无障碍与 Web 实现七个维度。

自动化证据：62 项核心测试、3 项 SSR 测试、66 项 Playwright 用例（真实 Google Chrome，单机）。日期：2026-09-15。

---

## 一、本轮修掉的问题

### 用户报告的缺陷

| # | 现象 | 根因 | 处理 |
| --- | --- | --- | --- |
| 1 | 左栏高亮一直停在第一项 | 选中透镜只写了水平位移；纵向侧边栏里每一项的水平位置都是 0 | 两个轴都跟踪；新增回归用例断言透镜顶边与当前项对齐 |
| 2 | 深色模式下对话框是白的 | 演示框把外观写死成浅色，而 `<dialog>` 走浏览器顶层渲染，白色面板盖在深色页面上 | 演示框跟随站点外观，用户手动切换后才固定；新增三种浮层的深色断言 |
| 3 | 输入框默认高亮，边框丑且重叠 | 全局规则与字段容器各画了一个 3px 环，且用 `:focus-within`（指针点击和自动聚焦都会亮） | 统一为一个 2px 环，改用 `:focus-visible`；库内以足够的优先级压住输入框自身的环，应用样式表的加载顺序无法破坏它 |
| 4 | GlassSheet 没有开关动画 | 缺 `@starting-style` 与 `allow-discrete`，背景遮罩也没有过渡 | 补齐升起/落下与遮罩淡入淡出；减少动效时直接切换 |
| 5 | 组件演示会改变整站路由 | 列表行与标签栏演示用的是真实跳转链接 | 统一为不跳转的演示链接；新增用例逐个点过去断言地址栏不变 |
| 6 | 演示页形态、左栏命名 | 单个大演示块，左栏只有英文名 | 改为多示例卡片 + 右侧目录；全站统一「中文 英文」 |
| 7 | 文案有开发术语 | 站点文案写的是实现与验证过程 | 全站重写为面向使用者的说明；移除三个实验室页面 |

### 审查中另外发现的

| # | 严重度 | 问题 | 处理 |
| --- | --- | --- | --- |
| A | Major | 首屏主题脚本是内联的，违反预览服务器的 CSP | 加上 nonce 占位；用例断言零违规 |
| B | Major | 打包会丢掉 `"use client"`，导致包无法在 Next.js App Router 的服务端组件里被导入 | 产物顶部统一加一条；发版检查里明确要核对 |
| C | Minor | 触摸端补足命中区的伪元素同时写了 `inset`、`inset-inline`、`translate` 和 `transform`，相互冲突 | 重写为从中心扩展的单一写法 |
| D | Minor | 材质的模糊、饱和度、高光角度在 CSS 与 TypeScript 里各声明了一份，改 CSS 那份不生效 | 删除重复项，注明唯一来源 |
| E | Minor | 演示侧栏行 40px、文档左栏 34px，低于触摸端下限 | 触摸设备上统一补到 44 |

## 二、逐组件结论

全部 27 个组件页都通过了同一套基线检查（页面完整、无控制台报错、无横向溢出、示例可展开代码、属性表与键盘说明齐全）。下面只记录每个组件在设计规则上的关键点与结论。

| 组件 | 关键规则 | 结论 |
| --- | --- | --- |
| 文本 Text | 用内建样式建立层级；11px 是下限；标题层级不推断 | ✓ 全站最小字号断言为 11px |
| 卡片 Card | 内容层不用玻璃；嵌套圆角同心 | ✓ 用例断言卡片不采样背景 |
| 列表 List | 可点的行是真链接或按钮；分区标题不全大写；分隔线内缩 | ✓ |
| 标准材质 MaterialView | 内容层的半透明手段，不带折射与高光边 | ✓ 用例断言无 rim、无装饰层 |
| 分隔线 Divider | 栏之间不用它 | ✓ |
| 按钮 GlassButton | 一屏一个主操作；触摸端命中区 44 | ✓ 用例断言每个示例只有一个 prominent |
| 分段控件 SegmentedControl | 可拖动，拖动中即时切换；原生 radio | ✓ 三项拖拽用例 |
| 开关 GlassSwitch | 可甩，方向决定结果；打开态系统绿 | ✓ |
| 滑块 GlassSlider | 旋钮静止安静，仅拖动时抬升为玻璃 | ✓ 用例断言静止态装饰不可见 |
| 步进器 GlassStepper | 两个具名按钮，不是数字框 | ✓ |
| 进度 GlassProgress | 能算出进度就不要转圈；减少动效时停止 | ✓ |
| 徽标 GlassBadge | 颜色不是唯一信息；需要说明数什么 | ✓ |
| 输入框 TextField | 真实标签；错误不只靠红框；≥16px 防缩放 | ✓ |
| 搜索框 SearchField | 独立玻璃面；焦点环在容器上 | ✓ |
| 工具栏 GlassToolbar | 栏无背景，分组才是玻璃；图标与文字不同组 | ✓ 混排时开发模式告警 |
| 标签栏 TabBar | 是 nav 不是 tablist；搜索独立一格；宽屏变侧边栏 | ✓ |
| 侧边栏 Sidebar | 大玻璃更厚且不翻转明暗 | ✓ |
| 标签页 GlassTabs | 就地换内容，与页面导航区分 | ✓ |
| 导航栏 NavigationBar | 大标题在场时紧凑标题隐藏 | ✓ |
| 滚动边缘 ScrollEdge | 渐进溶解而非色块；一个滚动区一个 | ✓ |
| 气泡面板 GlassPopover | 从触发控件长出并锚定；Escape 回焦 | ✓ |
| 菜单 GlassMenu | 完整键盘模型；每组约七项 | ✓ |
| 底部面板 GlassSheet | 拖动跟手、弹簧停靠、满高变不透明 | ✓ 本轮补上进出动画 |
| 警告框 GlassAlert | 标题加粗左对齐；破坏性时焦点在取消；Escape 等于取消 | ✓ |
| 操作表 GlassActionSheet | 破坏性排最后，取消分开 | ✓ |
| 对话框 GlassDialog | 原生 dialog 提供焦点约束与背景隔离 | ✓ |
| 轻提示 Toast | 可逆操作给撤销而不是弹窗；悬停暂停计时 | ✓ |

## 三、系统偏好

浏览器内实测（通过站点自带的偏好开关，叠加在系统设置之上）：

| 设置 | 预期 | 实测 |
| --- | --- | --- |
| 默认 | 行进高光 + 背景模糊 | 圆锥渐变描边，`blur(14px) saturate(…)` |
| 增强对比度 | 接近黑白 + 对比边框，关掉折射 | 描边变实色边框，背景滤镜为 `none` |
| 减少透明度 | 背景滤镜关闭，材质变实 | 背景滤镜为 `none`，边缘保留 |
| 减少动效 | 关闭弹性、位移、拖动形变 | 用例断言分段控件不再拉伸 |
| 强制颜色 | 交给系统调色板 | 用例断言折射路径关闭 |

## 四、仍然没做的

| # | 严重度 | 问题 | 说明 |
| --- | --- | --- | --- |
| R1 | Major | 屏幕阅读器实机验证 | 自动化只能证明角色和键盘路径是对的，证明不了朗读顺序是否自然 |
| R2 | Major | 玻璃在真实合成背景上的对比度 | 玻璃的最终颜色取决于背后是什么，把两个色值填进计算器不算数 |
| R3 | Minor | Safari / Firefox 的退化观感 | 代码路径是对的，但没有人用眼睛确认过退化后仍然读得出是一种材质 |
| R4 | Minor | 公开 API 里混进了内部装配函数 | `usePopover`、`triggerElement`、`lockScroll` 属于内部，下个破坏性版本收敛 |
| R5 | Minor | 性能预算未实测 | 「一屏二十块玻璃」是经验值，没有在低端设备上验证过 |

R1 与 R2 是自动化替代不了的，属于发布前的人工门槛，在 `docs/action-items.md` 中保持「待验证」。

## 五、结论

用户报告的七组问题全部修复，其中五组各自有回归用例守住；审查中另外发现并修复了五个问题，其中 CSP 违规和丢失 `"use client"` 两项会直接导致包在真实项目里用不了。

最能改变观感的三处：**把左栏高亮修对**（之前整个导航看起来是坏的）、**演示页改成可查阅的形态**（之前是一堆挤在一起的控件）、**文案换成人话**（之前读起来像验收报告）。
